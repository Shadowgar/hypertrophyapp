## Implemented application boundary, 2026-10-19

The owner authorized the existing original three-day Full Body planner to enter the actual application under clearly disclosed provisional numerical policies. This authorization is distinct from scientific approval; no external reviewer or fabricated endorsement is required for continuing implementation. `ApplicationLifecycle` reuses the immutable proposal/consent protocol, revalidates content and calendar freshness under the User lock, and atomically publishes the accepted snapshot and lifecycle event. A version-bound single acknowledgement covers all backend workload differences and provisional assumptions.

The application never supplies synthetic equipment loads, inferred historical effort or generic seed loads. Today supports user calibration and actual receipt logging; sparse/incomparable evidence produces no new load recommendation. A completed workout describes effective logged sets, not hypertrophy or a requirement to train through pain. Active snapshots cannot be rewritten; occupied/ambiguous weeks require visible resolution. [Implementation evidence](../evidence/2026-10-19-m4-application-integration.md) names what is verified and what remains unfinished.

## Active plan changes, owner-authorized 2026-10-20

The existing application lifecycle now supports two explicit operations. A date amendment previews and confirms the same ordered workout slots through PR #83's validator/placer, retaining the plan ID, exercise identities, prescription, original consent and placement history. Confirmation binds the account session, proposal/placement revisions and calendar/prescription digest under the existing account transaction. Materialized execution snapshots retain their dates and prescriptions even after all receipts are voided; only remaining unstarted slots can move within that local week. Cross-week movement and timezone changes return explicit conflicts rather than rewriting history.

Replacement runs the existing original planner and compact version-bound acknowledgement. Its audit binds the old owned active plan, exact prescription/dates, placement revision, proposed version and preserved execution snapshots. Activation atomically supersedes an entirely unstarted same-week Customized plan and publishes its accepted successor; a started week remains intact while an explicitly accepted next-week program is published separately. No partial-week carryover, automatic cancellation or Authored replacement permission is inferred. Changes to the old plan, receipts, inventory, neighbors or authorization invalidate a pending command. Replacement exclusions are command-local, never inherited permission.

[Implementation and qualification](../evidence/2026-10-20-m4-active-lifecycle.md) records this bounded behavior and its limitations. Numerical policies remain provisional, metadata scoring remains frozen, observed-empty source coverage remains distinct from authoritative rest, and `source_verified=False` is unchanged. Release and production operations remain separately authorized.
