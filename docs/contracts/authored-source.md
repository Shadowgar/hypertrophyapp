# Authored source contract

Status: **Owner-approved fidelity direction; proposed representation/qualification details**. Owners: artifact maintainer (compiler), engine owner (adapter), product reviewer (permissions). Governing [ADR-003](../adr/0003-authored-source-immutability-and-compilation.md). No source/artifact change is authorized by this document.

## Inputs and outputs

Input is a licensed original workbook/manual with stable source identity and cryptographic digest, admitted program/version and source interpretation. Keep source bytes unchanged. Compiler inputs include importer/schema versions and an explicit interpretation/exception register. Generated guides are diagnostic output, never runtime doctrine.

Output is a versioned compiled program containing every source week/session/slot, raw instructions plus typed set prescriptions, source-approved choices and relationship constraints. Attach original/compiled digests, parser version, diagnostic counts/dispositions and provenance. Runtime consumes compiled artifacts; raw source is offline. Separate Phase 1/Phase 2 identities and executable rules remain intact.

## Invariants and transformations

Preserve working sets, each set’s reps (numeric range, AMRAP or other declared kind), prescribed RPE/RIR, intensity techniques/children, warm-ups, rest, notes, meaningful order/pairs/primers and source block/progression structure. A numeric field cannot absorb unknown or nonnumeric intent. Raw strings survive alongside interpretation; uncertainty is represented explicitly.

A source slot identifies week/session/position, not just exercise catalog ID. Repeated exercises must not deduplicate. Source-approved alternatives require provenance and later explicit user confirmation before execution; a general library similarity score is not source permission. A conflict affecting one slot cannot change unrelated programming.

Compilation can normalize labels/units with a versioned lossless mapping. It cannot silently prune rows, flatten differing set targets to the first set or promote source IDs into generated-layout authority. Source updates create new versions; old completed prescriptions and prior artifact hashes remain reconstructible.

## Failure and fidelity qualification

Diagnostics classify every admitted or rejected source row and unresolved semantic interpretation. A skipped required exercise row blocks fidelity certification/admission for the affected version; “warning” is not an exemption. Missing licensed fixtures produce unqualified evidence, not certification of current JSON. An explicit exception names the source slot, reason, reviewer and scope; it cannot erase source loss.

AUD-20260928 established Phase 2’s five omitted AMRAP push-ups in weeks 6–10, each two working sets: 310 source versus 305 retained. A future repair must restore them with correct slot identity and following-row lineage; do not claim this documentation restored the artifact. Phase 1’s 315-row parity and 80 unrestricted multiset cases remain useful but limited.

Acceptance: independently parse licensed source, compare source → compiled → runtime/execution at every required field and relationship/order, reconcile all diagnostics and record unchanged source hashes. Example: AMRAP retains typed kind and two sets; a top/backoff pair retains different targets; two identical exercises retain separate source slots. A source-approved substitution changes performed variant only after confirmation. Qualify all admitted weeks/phases with restrictions/time/recovery negatives. Exact source fixture retention/licensing is an unresolved operational decision, documented in the [evidence migration plan](../evidence/README.md#audit-reference-and-migration-plan).
