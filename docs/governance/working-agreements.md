# Working agreements

Active documentation procedure under the [constitution](constitution.md), 2026-09-28. [Original agreements](../process/Working_Agreements.md) remain supporting history.

Excel/workbooks govern authored prescriptions; manuals/doctrine contribute reviewed compiled knowledge at build time. Preserve licensed provenance and unresolved interpretation rather than filling gaps with runtime inference. Separate immutable source, deterministic policy and execution. API/router orchestration does not acquire extra domain authority merely because the audited implementation currently contains policy there.

Preview and apply must use the same versioned decision inputs/interpreter. Trace actual profile/context/rules and any fallback. Additive schema/version/compatibility changes must name affected consumers and migration/recovery evidence; prefer bounded changes to wholesale architecture replacement. Keep source build changes, runtime changes, schema migration and metadata scoring activation in separate reviewable scopes.

Every change records controlling requirement, ADR status, affected contract, allowed authority, meaningful verification and limits. Update links/context together. Old mini-validation output is historical and may suppress failures; only applicable honest gates from [release qualification](../quality/release-gates.md) can support a release claim. A clean branch or passing subset is not owner acceptance.
