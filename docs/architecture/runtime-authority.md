Activation rechecks that dependency and adjacent plan content under the existing user lock. Saved unstarted re-placement retains its original source content; started or consented snapshots remain frozen. See the [bounded plan](../plans/m2b-next-week-scheduling.md); qualification is separate from release acceptance.

## M2A-2 candidate: authored warm-ups

The bounded [warm-up plan](../plans/m2a-authored-warmup-guidance.md) gives Authored warm-up guidance one runtime owner: `core_engine.authored_warmups.build_authored_warmup_guidance`. It consumes the immutable source count/instructions, the compiled Phase 1/2 warm-up protocol, the M2A-1 qualified working-load decision and declared load context. The API resolves source provenance and captures scoped advice; Today displays the server result and records editable actual values. Neither adapter owns a second authored percentage ladder.

Today, Progress and Summary share one response-local `AuthoredHistorySnapshot` through the API projection adapter. The existing user-filtered history, effective receipts, exposure summaries and comparison keys are loaded once; each projection retains its own current context, performed-date cutoff and core decision. The snapshot is bound to its user and database session, with no global or cross-request cache. Commands/retries continue to load fresh evidence. [Issue #80 qualification](../evidence/2026-10-13-authored-history-snapshot.md) records measured performance and equivalence limits.

The old core `warmups.compute_warmups` and browser `warmupsFromWorkingWeightLb` remain confined to existing Generated/estimate flows. Their differing rounding/minimum behavior is not authority for Authored. The new owner recognizes the existing source ladders only when the supplied protocol matches the qualified source version. Zero/absent counts yield no invented sets; textual counts remain manual. Declared increments bound suggestions but do not establish a full inventory, machine minimum or available plates. Warm-up receipts remain outside required working-set completion and completed-exposure progression. This candidate mapping is not whole-M2A or release acceptance.
