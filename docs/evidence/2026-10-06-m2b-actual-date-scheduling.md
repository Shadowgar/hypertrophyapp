## Model and decision ownership

The user selects 2–5 distinct local calendar dates in the current Monday–Sunday week and explicitly confirms an IANA timezone. Invalid/duplicate/out-of-week/unsupported inputs reject, without hidden correction. Past dates within that week are explicit placements with a warning; they never create performed history. There is no manufactured UTC workout time. A nullable persisted user timezone owns the local clock; changing it is rejected pending a separately reviewed history policy.

`core_engine.selected_date_scheduler` validates the aware planning instant and owns date placement. The M1-C `authored_redistribution` owner enumerates complete contiguous source-unit allocations, retaining ordered source slots, repeated slots, working sets, source-scoped variants, unresolved slots and hard relationships. Its versioned lexical objective minimizes declared-primary-muscle working-set overlap on consecutive calendar dates, then working-set imbalance, squared deviation and stable source cuts. Explicit source minimum-rest constraints reject infeasible candidates. No arbitrary scientific weights or recovery claims are introduced.

New placements use the exact selected dates. Existing same-count plans, including undated legacy plans, keep their grouping/prescriptions/occurrence-to-source-slot mappings. Count changes supersede an entirely unstarted plan, retaining its source payload and replacement lineage with disjoint new occurrence identities. The API owns authenticated activation, expected revisions and user-row locking. The preview returns a versioned canonical prescription digest. Week requires that digest for activation, and the API verifies it under the user lock before any write; changed generation inputs or a newly created undated plan cannot silently replace the reviewed content. The digest includes ordered source work, typed/raw prescriptions, loads, permissions, block identity and selected local dates, excluding ephemeral identity/projection metadata and trace timestamps. Direct API generation without preview remains an explicit supported path. Activation also revalidates the current local week with a fresh aware instant after acquiring the lock, rejecting an expired week without writes. Any execution or consent snapshot freezes the week's placement, including undone/completed work. Dated users cannot invoke server-clock count-only current regeneration, even at opposite local/server week boundaries. New local weeks use canonical generation history rather than resetting the authored source week.

Initial Auto selection uses the existing deterministic selection owner on a transient profile. Preview cannot add that profile, flush or commit planning state. `GET /plan/scheduling-context`, `POST /plan/selected-dates/preview` and selected-date `POST /plan/generate-week` carry explicit week/timezone/revision inputs. Traces include source/rule digests, declared workload, gaps, neighbor-context completeness, objective and limitations. Unknown adjacent weeks and missing muscle labels remain unknown; duration is explicitly uncalibrated.

Today selects the occurrence whose date equals the persisted timezone's local today. It resumes the same partial/completed occurrence and shows a clear rest state on dates without a workout. Week has seven accessible date checkboxes, selected count, preview followed by explicit activation, real date/session labels, warnings and focus/visibility/pre-command stale-week/revision checks. The inherited server-Sunday gate no longer blocks date placement. Weekly-review status and submission retain their existing policy but use the persisted scheduling local date. Today awaits that same clock for soreness lookup, save and Skip; dismissal belongs to one local date. A modal left open across midnight is discarded and restarts through the review gate without writing stale answers or skipping the new day. Check-In submits the displayed server-provided review week explicitly. Review submission refreshes the authenticated user after locking so first-time timezone activation committed while waiting cannot leave a stale server-date fallback.

Dated receipt history is owned by `api.history_dates` under `occurrence-performed-date-v1`: an owner-matched occurrence's persisted `scheduled_date` determines date/window membership, with unchanged audit-timestamp calendar dates for null/legacy or foreign-owner references. SQL applies user, effective-void and date filters before fetching or limiting rows. Core calendar completion/PR badges, strength weeks and volume heatmaps consume that explicit date; receipt ordering, displayed timestamps and amendment lineage remain unchanged. Weekly-review summaries use the same membership, including corrections entered in a later week, and exclude retained superseded plan targets before selecting the prior plan. Analytics applies both occurrence-date bounds through local today, excluding early-logged future placements from the advertised current window while retaining their receipts for explicit day queries. History's rolling calendar windows use the scheduling context's local date, with date-only arithmetic and explicit retry on unavailable/invalid clock data. This fixes the opposite UTC/local Sunday–Monday directions without reinterpreting undated legacy history.
