## Implemented application behavior

`customized_rescheduling.CustomizedRescheduling` runs the existing #83 date validator/placer and accepted C1 minimum-gap rule. Preview writes an append-only proposal revision without changing placement. A separate explicit confirmation binds its digest, session, proposal and placement revisions, source freshness and complete prescription; the existing account lock/transaction publishes the same WorkoutPlan at the next placement revision. Original consent, stable workout/exercise IDs, frozen snapshots, placement history and retry receipts remain. Unknown neighboring coverage is disclosed, ambiguous coverage fails closed, and `source_verified=False` stays explicit. A started slot cannot move after correction or void; remaining slots can move without rearranging the frozen ordered slots. Cross-week rescheduling/timezone changes return conflicts and the supported future-program alternative.

`customized_replacement.CustomizedReplacement` uses the existing original planner and compact consent lifecycle. The snapshot/summary retain the complete old/current prescriptions, dates and preserved execution snapshots beside the proposed program; one explicit acknowledgement binds both versions and all existing backend science/workload audit. An unstarted same-week plan is superseded atomically with the successor's activation and both lifecycle heads, retaining the old plan and consent. A started current week remains active while the accepted next-week plan is published separately; no partial-week carryover is invented. Concurrent changes invalidate the target binding; declined/cancelled previews leave the current plan unchanged. A replaced unstarted occurrence cannot accept a delayed log command. Account-scoped active discovery reads current/next weeks only.

The existing `/customize` page exposes active programs, date previews/confirmation, complete original/current/proposed prescriptions, replacement consent and decline/cancel. Week and Today link back to that lifecycle. Customized Week displays unknown loads as exercise-specific calibration pending and known declared loads in kg; absent legacy mesocycle/coverage metadata is not presented as measured state. A new account's canonical null inventory revision is handled only when actual revision is zero with no saved profile; saved inventory freshness remains enforced.

The source calendar permits older frozen Customized placement revisions only with retained placement/date/timezone proof and an unchanged current prescription. Same-revision Authored substitution/constraint receipts retain their existing execution authority; no Authored placement/prescription mutation route is added.
