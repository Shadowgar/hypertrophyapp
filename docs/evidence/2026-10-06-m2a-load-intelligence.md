## Runtime owner and evidence

[Core load intelligence](../../packages/core-engine/core_engine/load_intelligence.py) owns exposure qualification, comparability, deterministic increase/hold/decrease/monitor and temporary remaining-set load advice. Inputs are frozen typed source sets/lineage, effective actual receipts, performed variant, declared load context and the named authored ruleset. Outputs include action, canonical kg load or null, physical and qualified completed counts, actual-RPE sufficiency, failure streak, reason codes, source/rule/evidence hashes and equipment limitations. No runtime LLM, statistical growth confidence or prescription mutation is introduced.

One completed exposure covers every required working ordinal exactly once in one exercise/workout occurrence. Warm-ups, technique children, voids and identical retries cannot add exposures; incomplete or duplicate-ordinal evidence cannot masquerade as completion. Physically completed evidence and qualified comparable evidence have separate counts. Missing actual RPE remains unknown. Comparisons retain source program/version/session/slot, typed dose/effort/technique, performed variant and explicit unit/basis/equipment identity; week/date and week-specific source-set IDs do not block compatible later-week learning. Different repeated positions and confirmed variants have independent cohorts.

Phase 1/2 canonical source rules retain their existing top-of-range increase, in-range hold and reduction after two under-target exposures. This slice applies their named percentages to completed comparable evidence: it does not invent a two-success threshold or import Generated progression policy. One poor completed exposure holds rather than establishing repeated decline. Unknown targets/RIR, AMRAP/bodyweight/assistance, source hard-load instructions, mixed working loads, unknown context or unavailable feasible increments abstain. A partial set below the typed rep minimum and above the explicit source RPE maximum can offer the named reduction for remaining sets only; it cannot become a completed long-term exposure.

[API persistence](../../apps/api/app/workout_load_state.py) derives owner-bound effective receipts from frozen occurrences. Under the existing user-row lock, log/correction/undo rebuild the authored cache and advice atomically with the retained command result. New captured v2 receipts separate offered recommendation, actual chosen weight, context, override reason and trace. Legacy v1 replay keeps its original owner and absent-field request digest normalization. Old command retries cannot resurrect voided evidence. Read/preview paths do not persist advice, occurrences or projections.

The additive [0022 migration](../../apps/api/alembic/versions/0022_authored_load_states.py) creates only `authored_load_states`, with unique `(user_id, comparison_key)`, source identity and reconstructible JSON state. Existing Generated `ExerciseState` and its old per-set baseline stay separate. No legacy RPE, basis, inventory or qualified context is backfilled. Existing dev-only user cleanup includes the new cache under its unchanged disabled-by-default boundary; qualification uses synthetic users only.

Today captures optional actual RPE 0–10 separately from source targets. Blank is null; correction omission preserves RPE and explicit clearing makes it unknown. Qualified server advice prefills untouched drafts; overrides and pending requests retain their exact canonical load and command payload. Rounded lb display does not change an untouched canonical kg recommendation. Context preview is read-only and must match the recorded basis/equipment. Missing context gives monitor and an empty manual load draft. Receipt edits, undo and refreshed advice preserve authored exercise/dose/targets/order/relationships/techniques/rest.

Known user-declared kg/lb increments round from an actual attainable baseline. Unknown inventory uses the named existing 0.5 kg compatibility increment with an explicit unverified-equipment limitation. Machine stacks require an equipment reference; this does not certify full inventory, calibrated machines, available bounds or plate combinations.
