# Metadata accounting and scoring boundary

Owner-approved deterministic/source boundaries; accounting conventions and future scoring mechanisms require review. [Catalog owner](../architecture/exercise-catalog.md), [runtime authority](../architecture/runtime-authority.md), [GEN](../requirements/catalog.md#gen)/[PERF](../requirements/catalog.md#perf), [M4 plan](../plans/generated-stabilization.md).

Keep planned source dose, allocated dose, effective performed sets and reported muscle accounting distinct and reconcilable. Retain source-slot/variant/occurrence identity and set kinds; warm-up/technique child sets cannot become extra comparable work exposures. Missing/uncertain metadata must be visible, with versioned convention and denominator rather than invented precision.

Trace values describe actual consumed policy or are explicitly trace-only. Source substitutions require confirmation even if metadata ranks another exercise. Collision handling cannot deduplicate distinct required slots by exercise ID or mutate unrelated Authored dose. Metadata-v2 scoring is frozen; fatigue/time/role/overlap/substitution/skill scores remain no-op. Accounting corrections do not authorize reactivation.

Future acceptance needs source/plan/log/report reconciliation, variant and repeated-slot cases, unknown coverage, deterministic outputs and before/after tests for each explicitly approved scoring signal. Historical numeric weights and quality-report scores are reference proposals/results with original limits, not current qualified thresholds. [Legacy model](../architecture/EXERCISE_METADATA_MODEL.md) and [retained generated reports](../evidence/legacy/README.md) preserve detailed history.
