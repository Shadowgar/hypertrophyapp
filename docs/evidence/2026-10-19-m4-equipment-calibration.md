## Implemented application behavior

- Authenticated `/customize` now edits a durable account-owned location inventory: actual labeled weights/counts, matched dumbbells, bar/plate counts, machine labels or explicit uniform stack bounds/increments, kg/lb, exact variant assignments, setup/range notes and availability limits. Additive migration `0023_customized_inventory` creates the profile table and a date-cohort index without backfill. Revision checks serialize on the existing User-first PostgreSQL lock; duplicate retries return the saved document, conflicting edits return 409. Account/session revocation and ownership remain enforced.
- Application generation normalizes directly into the established CustomizedProfile. Inventory filters the descriptive catalog, contributes attainable canonical-kg loads, and binds immutable proposal content and compact consent. Inventory edits invalidate stale acceptance, preserve stored workouts/receipts, and do not reinterpret Authored profiles. Unavailable/unassigned variants and absent matching implements produce explanations; no default plate sizes, increments or working weights are inferred.
- Optional historical 1RM/e1RM records retain their own units, date, exact setup fingerprint and method/reference. A setup edit cannot silently rebind a report; re-entry establishes a new report ID. Reports remain information only. Barbell inventory is retained/enumerated, but this existing pilot catalog has no barbell exercise variant; no dumbbell-to-barbell transfer is inferred. No maximal test or percentage conversion is required.
- Existing C1 calibration admits effective comparable completed sets first, then qualified optional information, then guided exercise-specific calibration. Actual RIR/RPE stay distinct from targets; technique/pain remain unknown unless entered. Exact prescribed set indices are part of the comparison cohort. The versioned provisional wrapper can offer one attainable higher load up to 10% after a complete, easy top-rep exposure; missing context, effort, quality, pain status, inventory, matching identity or complete coverage abstains. This is a software operating bound, not a physiological guarantee. Corrections and voids reconstruct advice and retain the original audit.
- Today uses the same calibration owner for load preview, receipts, corrections and completion summaries. Canonical units and exact setup are explicit. The browser cannot add legacy weak-point names, swaps or explanations to the original plan. Dated audits are canonically JSON-serialized before PostgreSQL persistence.
- Legacy generated aliases remain readable for history, but generation/next-week/coaching/frequency mutation routes direct the user to consent-bound `/customize`. The live source-replayed constructor and conflicting generated numerical floors/repairs were removed from `plan.py`; pure compatibility/debug adapters remain. Focused tests replace obsolete live-generator assertions with a seven-route no-mutation matrix for both aliases, manual/auto mode and fresh/retained history. Authored source-preservation bodies remain intact.
