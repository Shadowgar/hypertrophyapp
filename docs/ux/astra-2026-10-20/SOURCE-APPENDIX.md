## Account entry and full-profile persistence (F01/F02)

### Alternate onboarding login

The “I already have an account” handler changes `authMode` to login and moves directly to the account phase; it does not load the existing profile into questionnaire state: [apps/web/app/onboarding/page.tsx:1479-1491](https://github.com/Shadowgar/hypertrophyapp/blob/fc3bd0c7b93c9d3232e6aec758e16efcca6ac583/apps/web/app/onboarding/page.tsx#L1479-L1491). Initial questionnaire state includes 180 lb, empty equipment/restrictions and no chosen days; program selection initially is null: [apps/web/app/onboarding/page.tsx:380-404](https://github.com/Shadowgar/hypertrophyapp/blob/fc3bd0c7b93c9d3232e6aec758e16efcca6ac583/apps/web/app/onboarding/page.tsx#L380-L404). A restored draft can change these values, so “always writes exactly the defaults” would overstate the trace.

`submitOnboarding` resolves a token, stores it and **unconditionally** calls `saveOnboardingProfile` on success: [apps/web/app/onboarding/page.tsx:926-945](https://github.com/Shadowgar/hypertrophyapp/blob/fc3bd0c7b93c9d3232e6aec758e16efcca6ac583/apps/web/app/onboarding/page.tsx#L926-L945). That function resolves name/weight/days/location/equipment and POSTs the full profile, including restrictions, nutrition and program selection: [apps/web/app/onboarding/page.tsx:851-914](https://github.com/Shadowgar/hypertrophyapp/blob/fc3bd0c7b93c9d3232e6aec758e16efcca6ac583/apps/web/app/onboarding/page.tsx#L851-L914). Thus sign-in from this branch performs setup writes using current questionnaire/draft/default state. Dedicated Login instead obtains the token and navigates: [apps/web/app/login/page.tsx:20-43](https://github.com/Shadowgar/hypertrophyapp/blob/fc3bd0c7b93c9d3232e6aec758e16efcca6ac583/apps/web/app/login/page.tsx#L20-L43).

The router preserves an existing `generated_onboarding` document when the incoming answers omit that specific key; this limited preservation must not be mistaken for preserving all existing profile fields: [apps/api/app/routers/profile.py:400-408](https://github.com/Shadowgar/hypertrophyapp/blob/fc3bd0c7b93c9d3232e6aec758e16efcca6ac583/apps/api/app/routers/profile.py#L400-L408). It builds persistence values from the submitted fields, assigns each value, and commits: [apps/api/app/routers/profile.py:422-467](https://github.com/Shadowgar/hypertrophyapp/blob/fc3bd0c7b93c9d3232e6aec758e16efcca6ac583/apps/api/app/routers/profile.py#L422-L467).

The reset condition is **conditional**, not universal: incomplete→complete, selected-program binding change, or same-binding changed onboarding with no workout activity. That condition invokes `_clear_user_training_state`: [apps/api/app/routers/profile.py:410-461](https://github.com/Shadowgar/hypertrophyapp/blob/fc3bd0c7b93c9d3232e6aec758e16efcca6ac583/apps/api/app/routers/profile.py#L410-L461). Its source deletes the user's command/session/log/occurrence/load/plan/review/check-in and other training-state rows: [apps/api/app/routers/profile.py:107-119](https://github.com/Shadowgar/hypertrophyapp/blob/fc3bd0c7b93c9d3232e6aec758e16efcca6ac583/apps/api/app/routers/profile.py#L107-L119). No such operation was executed in this audit and no actual affected account is asserted. Even when this condition is false, the profile assignment still occurs.

After the save, explicit `full_body_v1` branches to `/customize`. Otherwise an unset selection can request/apply a recommendation, generation is attempted, and an initial weekly review is submitted. These are shared onboarding actions rather than a login-only completion path: [apps/web/app/onboarding/page.tsx:947-1005](https://github.com/Shadowgar/hypertrophyapp/blob/fc3bd0c7b93c9d3232e6aec758e16efcca6ac583/apps/web/app/onboarding/page.tsx#L947-L1005). Generation/review errors are swallowed before the success message. This establishes the intent/action mismatch without claiming every downstream request succeeds.

Success/failure/pending strings are set by the handler, but the only shared-status rendering is inside `devWipeEnabled`: [apps/web/app/settings/page.tsx:122-156](https://github.com/Shadowgar/hypertrophyapp/blob/fc3bd0c7b93c9d3232e6aec758e16efcca6ac583/apps/web/app/settings/page.tsx#L122-L156); [apps/web/app/settings/page.tsx:589-601](https://github.com/Shadowgar/hypertrophyapp/blob/fc3bd0c7b93c9d3232e6aec758e16efcca6ac583/apps/web/app/settings/page.tsx#L589-L601).
