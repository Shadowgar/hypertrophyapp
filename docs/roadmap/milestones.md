## Evidence, gates and decisions

A milestone requires goal/scope/requirements, dependency resolution, relevant automated and manual criteria, revision/environment/artifact-linked evidence, reviewed deviations and explicit owner acceptance. A plan, published document or passing subset is insufficient. Gate applicability follows controlling safety/mode/source/history invariants for changed/enabled capabilities; do not silently turn every feature proposal into a blocker.

The [evidence registry](../evidence/README.md#recorded-audit-baseline) preserves core 364/4, original API 430/18/8, selected recheck 12 passes, six behavioral API failures, web 51/1 and 102 test-global type diagnostics with isolation/snapshot limitations. No new runtime results supersede them.

Unresolved owner decisions before affected implementation: recovery availability/legacy JWT cutover; licensed source-fixture retention and source-approved-option ambiguities; legacy mode/occurrence/unit mapping; correction storage/concurrency strategy; started-date/carryover policy and local-week default; progression/comparability/confidence/spacing rules; operational RPO/RTO/ownership and session/ingress strategy; longitudinal protocol; target devices/offline scope. Desired outcomes and parallel ordering are established, while numerical mechanisms and release acceptance remain pending.
